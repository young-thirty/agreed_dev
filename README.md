# Agreed

고객 메시지가 들어오면 계약·과거 대화·티켓·GitHub 개발 상황을 확인해 요구를 분석하고, 바로 보낼 수 있는 답변 초안까지 만들어 줍니다. 티켓 생성과 상태, 최종 발송은 사람이 정합니다.

## 시작

```bash
pnpm install
pnpm dev
```

http://localhost:3000

## 시연 모드

이 브랜치는 **백엔드(`agreed_be`) 없이 혼자 돕니다.** 모든 서버 호출을 `mocks/`가 브라우저 안에서
받아 같은 응답 규약(`{ ok, data }`)으로 돌려주므로, `pnpm dev`만으로 전 화면을 끝까지 눌러 볼 수 있습니다.

| 파일 | 내용 |
|---|---|
| `mocks/projects.ts` | 프로젝트 · 채널 연결 · 주고받은 자료 |
| `mocks/tickets.ts` | 티켓과 거기 붙은 고객 메시지 · AI 분석 |
| `mocks/incoming.ts` | 시연 중에 새로 도착하는 고객 메시지 |
| `mocks/server.ts` | 경로를 보고 응답을 만드는 목 백엔드 |
| `public/demo/*.docx` | 화면에서 그대로 열어 보는 제안서 · 계약서 · 요구사항 정의서 · 회의록 |

화면 오른쪽 아래 **시연** 버튼에 두 가지가 있습니다.

- **새 고객 메시지 받기** — 새 메시지가 도착해 티켓이 생기고, 분석이 붙는 과정을 그대로 보여줍니다
- **처음 상태로 되돌리기** — 시연을 다시 찍기 위해 모든 판단을 지웁니다

판단·발송 표시는 `localStorage`(`agreed:demo-state:v1`)에 남아 새로고침해도 유지됩니다.

### 시연 시나리오

1. `/tickets` — 처리 필요 5건. 채널(Gmail · Slack)과 프로젝트가 한 줄에 보입니다
2. **예약 취소 정책 변경 요청** — 계약 범위 밖 판정 → **이렇게 판단한 근거**를 펼쳐 제안서 3.2와 계약서 제5조 원문 확인
3. **개발 상황 확인** — 저장소에서 구현·진행 중·남은 작업과 영향 범위를 접어서 보여줍니다
4. **확인 항목 만들기** → 추가 비용·반영 일정 입력 → **문의/요청/거절** 중 하나와 말투를 골라 초안 생성 → **보냈다고 표시**
5. **카카오 알림톡 연동 일정 문의** — 분석 중 → 솔루션 생성 중 → 결과까지 두 단계가 순서대로 나타납니다
6. 프로젝트 → **파일** 탭에서 계약서를 열어 근거 원문 확인, **채널 연결** → **가져오기**로 새 티켓 생성
7. 시연 패널의 **새 고객 메시지 받기** — 알림이 뜨고 목록 맨 위에 새 티켓이 붙습니다

### 백엔드에 붙일 때

```bash
NEXT_PUBLIC_DEMO=0
NEXT_PUBLIC_API_BASE_URL=http://localhost:8000
```

`lib/api-client.ts`의 `DEMO`만 꺼지면 목을 거치지 않고 실제 FastAPI로 나갑니다. `mocks/` 폴더와
`components/DemoPanel.tsx`는 그때 통째로 지울 수 있습니다.

## 화면

| 경로 | 내용 |
|---|---|
| `/tickets` | 티켓 목록 (처리 필요 · 전체 · Active · Done · Reject). 새 고객 메시지는 관련 티켓에 붙고, 없으면 Active 티켓으로 새로 들어온다 |
| `/tickets/[id]` | 고객 메시지 → AI 분석 → 내 판단 → 답변 초안 + 이 티켓의 지난 대화 |
| `/projects` | 프로젝트 목록 |
| `/projects/[id]` | 티켓 · 파일 · 채널 연결 |
| `/settings` | Gmail · Slack · GitHub 계정 연동 |
